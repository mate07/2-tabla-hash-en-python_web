Colisiones y métodos de resolución

Comprender las causas y consecuencias de las colisiones, implementar mecanismos de resolución y comparar su impacto en el rendimiento de las tablas hash.

Introducción

Las tablas hash permiten almacenar y recuperar información de manera eficiente mediante funciones hash que transforman claves en índices de almacenamiento. Sin embargo, cuando diferentes claves generan el mismo índice, se produce una situación conocida como colisión (collision).

Las colisiones constituyen uno de los principales desafíos en la implementación de tablas hash, debido a que pueden afectar el rendimiento de las operaciones de inserción, búsqueda y eliminación.

Para solucionar este problema, existen mecanismos que permiten almacenar varios elementos sin perder información. Entre los más utilizados se encuentran el encadenamiento separado (Separate Chaining) y el direccionamiento abierto (Open Addressing).

Comprender estos mecanismos permite diseñar tablas hash capaces de administrar múltiples registros, mantener la integridad de los datos y aprovechar eficientemente el espacio de almacenamiento.

3.1 Concepto de colisión en una tabla hash

Una colisión ocurre cuando dos o más claves diferentes producen el mismo índice después de aplicar una función hash.

Esta situación puede presentarse incluso cuando la función hash está correctamente diseñada, debido a que la cantidad de claves posibles generalmente es mayor que la cantidad de posiciones disponibles.

Ejemplo conceptual

Consideremos una tabla hash con diez posiciones y la siguiente función:

h(k) = k mod 10

Se desean almacenar las claves 15, 25 y 35.

Clave Operación Índice
15 15 % 10 5
25 25 % 10 5
35 35 % 10 5

Representación de una colisión

Índice 5
Clave 25
Índice 5
Clave 35
Índice 5
↓
Posición 5

Tres claves necesitan una misma posición.

¡Colisión detectada!

Ejemplo en Python

def funcion_hash(clave, capacidad):
    return clave % capacidad


capacidad = 10
claves = [15, 25, 35]

for clave in claves:
    indice = funcion_hash(clave, capacidad)
    print(f"Clave {clave}: índice {indice}")
Resultado: 
Clave 15: índice 5
Clave 25: índice 5
Clave 35: índice 5

Una implementación correcta debe permitir conservar todos los elementos y diferenciarlos utilizando sus claves originales.

3.2 Causas y consecuencias de las colisiones

Las colisiones pueden producirse por diferentes factores relacionados con la función hash, la capacidad de almacenamiento y las características de las claves.

Causas principales

Capacidad limitada

La tabla dispone de un número finito de posiciones para almacenar claves.

Distribución deficiente

Una función hash puede concentrar numerosas claves en determinadas posiciones.

Claves con patrones similares

Algunas funciones generan coincidencias cuando las claves comparten características.

Factor de carga elevado

Una mayor cantidad de elementos incrementa las posibilidades de colisiones.

Consecuencias de las colisiones

  • Mayor tiempo de búsqueda: se necesitan operaciones adicionales para identificar una clave.
  • Inserciones más complejas: debe encontrarse una manera de almacenar los elementos que coinciden.
  • Degradación del rendimiento: una concentración excesiva incrementa el tiempo de ejecución.
  • Mayor uso de recursos: algunos métodos necesitan estructuras adicionales.
  • Riesgo de pérdida de información: una implementación incorrecta puede sobrescribir registros existentes.

Ejemplo de una implementación incorrecta

tabla = [None] * 10

claves = [15, 25, 35]

for clave in claves:
    indice = clave % 10
    tabla[indice] = clave

print(tabla[5])
Resultado: 
35
Problema identificado

Cada nueva inserción reemplaza el valor anterior. Solamente permanece la última clave almacenada. Una tabla hash correcta no debe sobrescribir registros diferentes únicamente porque generan el mismo índice.

3.3 Resolución mediante encadenamiento separado

El encadenamiento separado (Separate Chaining) permite almacenar varios elementos asociados con una misma posición de la tabla mediante una colección adicional.

En lugar de reservar una única entrada por índice, cada posición contiene una estructura capaz de almacenar múltiples registros. Pueden utilizarse listas enlazadas, listas dinámicas u otras estructuras.

Funcionamiento

  1. Se calcula el índice mediante la función hash.
  2. Se localiza la posición correspondiente.
  3. Si la posición está vacía, se agrega el primer elemento.
  4. Si ya contiene elementos, el nuevo registro se incorpora a la colección asociada.
  5. Para realizar una búsqueda, se revisan las claves almacenadas en dicha posición.

Representación del encadenamiento

Índice 5

Las tres claves comparten el índice 5, pero se conservan en una colección asociada a esa posición.

Implementación con listas en Python

capacidad = 10

tabla = [[] for _ in range(capacidad)]


def insertar(clave):
    indice = clave % capacidad

    if clave not in tabla[indice]:
        tabla[indice].append(clave)


insertar(15)
insertar(25)
insertar(35)

print(tabla[5])
Resultado: 
[15, 25, 35]

Cada posición contiene una lista que permite almacenar varias claves. Cuando se genera una colisión, los elementos se conservan dentro de la misma colección.

Búsqueda mediante encadenamiento

Continuando con la tabla creada anteriormente:

def buscar(clave):
    indice = clave % capacidad
    return clave in tabla[indice]


print(buscar(25))
print(buscar(45))
Resultado: 
True
False

La función calcula el índice y después busca la clave dentro de la lista correspondiente.

Ventajas y limitaciones

Ventajas Limitaciones
Implementación relativamente sencilla. Requiere estructuras adicionales.
Permite almacenar varias claves por posición. Las cadenas largas incrementan el tiempo de búsqueda.
Admite factores de carga mayores que 1. Puede utilizar más memoria por elemento.
Facilita la eliminación de elementos. Depende de una distribución adecuada.

3.4 Resolución mediante direccionamiento abierto

El direccionamiento abierto (Open Addressing) resuelve las colisiones buscando otra posición disponible dentro de la misma tabla.

A diferencia del encadenamiento separado, todos los elementos se almacenan directamente en las posiciones de la tabla. Cuando una posición está ocupada, se aplica una secuencia de exploración para localizar otro espacio.

Funcionamiento general

  1. Se calcula el índice inicial mediante la función hash.
  2. Se verifica si la posición está disponible.
  3. Si está ocupada, se calcula una nueva posición.
  4. El procedimiento continúa hasta encontrar un espacio libre.
  5. El elemento se almacena en la posición seleccionada.

A. Exploración lineal (Linear Probing)

La exploración lineal busca posiciones consecutivas cuando ocurre una colisión.

h(k, i) = (h(k) + i) mod m
  • h(k): índice inicial.
  • i: número de intento.
  • m: capacidad de la tabla.

Si las claves 15, 25 y 35 producen el índice inicial 5, pueden distribuirse consecutivamente.

Implementación en Python

capacidad = 10
tabla = [None] * capacidad


def insertar(clave):
    indice = clave % capacidad

    for _ in range(capacidad):
        if tabla[indice] is None:
            tabla[indice] = clave
            return True

        if tabla[indice] == clave:
            return False

        indice = (indice + 1) % capacidad

    return False


insertar(15)
insertar(25)
insertar(35)

print(tabla)
Resultado: 
[None, None, None, None, None, 15, 25, 35, None, None]

La operación (indice + 1) % capacidad permite continuar la exploración desde el inicio cuando se alcanza la última posición.

B. Exploración cuadrática (Quadratic Probing)

Utiliza desplazamientos basados en el cuadrado del número de intento para buscar posiciones alternativas.

h(k, i) = (h(k) + i²) mod m

Si el índice inicial es 5 y la capacidad de la tabla es 11, se obtiene:

Intento Operación Índice
0 (5 + 0²) % 11 5
1 (5 + 1²) % 11 6
2 (5 + 2²) % 11 9
3 (5 + 3²) % 11 3 
def exploracion_cuadratica(clave, capacidad):
    indice_inicial = clave % capacidad

    for intento in range(capacidad):
        indice = (
            indice_inicial + intento ** 2
        ) % capacidad

        print(indice)


exploracion_cuadratica(16, 11)

Esta técnica reduce la agrupación primaria que puede presentarse en la exploración lineal. Sin embargo, determinadas configuraciones pueden repetir posiciones sin recorrer toda la tabla.

C. Doble hashing (Double Hashing)

Utiliza una segunda función hash para determinar el desplazamiento entre las posiciones exploradas.

h(k, i) = (h₁(k) + i × h₂(k)) mod m
  • h₁(k): índice inicial.
  • h₂(k): desplazamiento calculado.
  • i: número de intento.
  • m: capacidad de la tabla.
def doble_hash(clave, capacidad):
    h1 = clave % capacidad
    h2 = 1 + (clave % (capacidad - 1))

    for intento in range(capacidad):
        indice = (
            h1 + intento * h2
        ) % capacidad

        print(indice)

Técnica Funcionamiento Consideración

Cuadrática Utiliza desplazamientos cuadráticos. Puede no visitar todas las posiciones.
Doble hashing Utiliza una segunda función hash. Requiere diseñar adecuadamente ambas funciones.

Consideración: en direccionamiento abierto, la eliminación puede requerir marcadores especiales para conservar la continuidad de las búsquedas y evitar que se pierdan registros durante la exploración.

3.5 Comparación de métodos y su impacto en el rendimiento

La selección del mecanismo de resolución de colisiones influye directamente en el uso de memoria, la velocidad de las operaciones y la complejidad de implementación de una tabla hash.

Encadenamiento separado frente a direccionamiento abierto

Criterio Encadenamiento separado Direccionamiento abierto
Almacenamiento Colecciones asociadas a cada índice. Posiciones dentro de la tabla.
Colisiones Agrega elementos a una cadena. Busca otra posición disponible.
Memoria adicional Generalmente mayor. Generalmente menor.
Factor de carga Puede superar 1. No puede superar 1.
Eliminación Relativamente sencilla. Debe preservar las búsquedas.
Rendimiento Depende de la longitud de las cadenas. Depende del factor de carga y exploración.
Implementación Fácil de comprender y extender. Requiere mayor control de posiciones.

Complejidad temporal

Operación Caso promedio Peor caso
Inserción O(1) O(n)
Búsqueda O(1) O(n)
Eliminación O(1) O(n)

El rendimiento promedio depende de una distribución adecuada de claves, del factor de carga y del mecanismo de resolución empleado.

Encadenamiento separado

Las cadenas extensas incrementan el número de comparaciones durante las búsquedas.

Direccionamiento abierto

Un factor de carga elevado puede aumentar las posiciones exploradas durante cada operación.

Criterios para seleccionar un método

  • Cantidad de elementos: volumen de información que administrará la tabla.
  • Disponibilidad de memoria: recursos necesarios para almacenar registros y estructuras adicionales.
  • Frecuencia de operaciones: cantidad de inserciones, búsquedas y eliminaciones.
  • Factor de carga esperado: crecimiento previsto de la estructura.
  • Simplicidad de implementación: complejidad del control de posiciones y colisiones.

Ejemplo integrador en Python

El siguiente programa implementa una tabla hash sencilla con encadenamiento separado para administrar productos mediante claves numéricas.

Cada entrada almacena un par clave-valor y permite resolver colisiones sin sobrescribir la información de otros registros.

Tabla hash mediante una clase

class TablaHash:
    def __init__(self, capacidad):
        self.capacidad = capacidad
        self.tabla = [
            [] for _ in range(capacidad)
        ]

    def hash(self, clave):
        return clave % self.capacidad

    def insertar(self, clave, valor):
        indice = self.hash(clave)

        for elemento in self.tabla[indice]:
            if elemento[0] == clave:
                elemento[1] = valor
                return

        self.tabla[indice].append(
            [clave, valor]
        )

    def buscar(self, clave):
        indice = self.hash(clave)

        for elemento in self.tabla[indice]:
            if elemento[0] == clave:
                return elemento[1]

        return None

    def mostrar(self):
        for indice, elementos in enumerate(self.tabla):
            print(f"{indice}: {elementos}")


# Crear tabla hash
productos = TablaHash(10)

# Insertar registros
productos.insertar(15, "Teclado")
productos.insertar(25, "Mouse")
productos.insertar(35, "Monitor")
productos.insertar(12, "Impresora")

# Mostrar distribución
productos.mostrar()

# Buscar un producto
print("Búsqueda:", productos.buscar(25))

5: [[15, 'Teclado'], [25, 'Mouse'], [35, 'Monitor']]
6: []

8: []
9: []
Búsqueda: Mouse

Análisis del ejemplo

Estructura

La clase crea una lista de colecciones para almacenar los elementos.

Función hash

El método hash() calcula el índice mediante el operador módulo.

Inserción

El método insertar() agrega registros y actualiza valores cuando la clave ya existe.

Búsqueda

El método buscar() localiza la colección y compara las claves almacenadas.

Visualización

El método mostrar() presenta la distribución de los elementos.

Resolución de colisiones

Las claves 15, 25 y 35 comparten el índice 5 sin sobrescribirse.

Aplicación práctica: el encadenamiento separado permite conservar múltiples registros cuyas claves generan el mismo índice, manteniendo las operaciones de almacenamiento y búsqueda dentro de una estructura organizada.

Síntesis

Las colisiones ocurren cuando diferentes claves generan el mismo índice dentro de una tabla hash. Aunque la función esté correctamente diseñada, estas situaciones pueden presentarse debido a la cantidad limitada de posiciones disponibles.

El encadenamiento separado permite almacenar varios registros asociados a un mismo índice mediante listas u otras estructuras. El direccionamiento abierto busca posiciones alternativas mediante exploración lineal, cuadrática o doble hashing.

Cada método presenta ventajas y limitaciones relacionadas con el consumo de memoria, el factor de carga y el rendimiento de las operaciones.

La selección de un mecanismo adecuado permite mantener la integridad de los registros y conservar un acceso eficiente a la información. Estos fundamentos son esenciales para implementar las operaciones de inserción, búsqueda, actualización y eliminación de una tabla hash.
